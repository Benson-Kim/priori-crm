The blockers

01 Stale OpenAPI artifact breaks the build Blocker

npm run build exits 2 on a clean checkout of develop.

The committed frontend/openapi.json is missing three paths and four schemas that exist on the running server:

paths   /api/v1/owner/modules
        /api/v1/owner/modules/{module_key}
        /api/v1/sales-desk/companies/{company_id}

schemas ModuleKey  ModuleSettingState
        ModuleSettingUpdate  ModuleSettingsResponse

build runs gen:api against that committed file, so the generated api-schema.d.ts lacks those types and tsc -b fails with 14 errors across pages/settings/modules.tsx, services/ownerApi.ts and hooks/useModuleAccess.ts.

Proved causal in both directions:

Schema sourcetscnpm run build
Committed openapi.jsonexit 2exit 2
Fresh export from the live APIexit 0exit 0

Fix — re-run the job's own command, python -m scripts.export_openapi ../frontend/openapi.json, and commit the result. Do not hand-edit it. This is the rule issue #51 already states: the artifact must be regenerated by the existing job after every backend merge.

Related: CI's npx tsc --noEmit runs against the root tsconfig.json, which is a {"files": [], "references": [...]} solution stub — it type-checks nothing. Only npm run build does. Worth pointing CI at tsconfig.app.json so this class of drift is caught earlier.

02 Billing-profile edit is impossible in the Sales Desk UI Blocker

Changing payment terms, tax treatment, or credit limit on any company fails 100% of the time.

updateBillingProfile (services/salesDeskApi.ts:806) sends no expectedVersion, but the endpoint requires it:

# api/app/modules/customers/router.py:211
expected_version: Annotated[
    int, Query(alias="expectedVersion", ...)
]   # required, no default

Reproduced in Chrome: the PATCH returns 422, the drawer surfaces the raw API error query.expectedVersion: Field required to the end user, and the field silently reverts.

The frontend also has nothing to send — GET /sales-desk/companies/{id} returns profiles without a version field, unlike BillingProfileResponse and CustomerResponse which both expose it.

Fix needs both halves — add version to DeskCompanyProfile, and pass it as expectedVersion from updateBillingProfile.

The endpoint itself is correct: supplying the profile's own version returns 200 and resets synced to false, and a stale version correctly 409s. The optimistic-locking design is sound — only the client wiring is missing. This blocks checklist item 1's "edit resets sync" step.

High severity

03 Parked deals are stranded High

Checklist item 2 — park → future pipeline → due notification → resume at recorded stage — is broken in the UI, even though every underlying API call works.

  • Park works. The drawer button is even labelled "Move to future pipeline".
  • The Future pipeline page never shows parked deals — only nurture prospects.
  • There is no resume or re-engage control anywhere in the UI, on any deal, in any state.

The badge disagrees with its own page: backdating a parked deal so it fell due moved the Future-pipeline badge 1 → 2 and the notification bell 17 → 18, while the page body still listed only the two nurture prospects.

POST /deals/{id}/resume works correctly when called directly — it returns the deal to its recorded stage and refuses on non-parked deals. It is simply unreachable from the UI.

Parked deals remain reachable via Pipeline → "All deals" (143 includes them, "Open" 124 excludes them), so this is a workflow gap rather than data loss.

04 Read-after-write race on every write endpoint High

POST /deals returns 201 with an id; an immediate GET of that id returns a service-level 404; an immediate retry with no delay returns 200.

--- iteration 27  deal=eb31cc7b…  GET=404  43ms
    {"error":"Deal with ID 'eb31cc7b…' not found",
     "error_code":"NotFoundException", ...}
    immediate retry 0: 200

3/40 GET-after-create failures

Reproduced at roughly 7% (3/40, then 2/30) on localhost. Expect worse under real network latency and load.

Cause: deals/service.py never commits — 0 commits, 5 flushes. The commit lives in the get_db dependency's post-yield block (api/app/common/database.py:134), so the response travels out through the BaseHTTPMiddleware stack before the INSERT is durable.

This is not deals-specific. Every write endpoint shares that session pattern, so any "create, then navigate straight to it" flow can 404 intermittently.

Fix direction — commit inside the handler or service unit of work before the response is built, rather than in dependency teardown. Largest blast radius of anything here; worth its own change.

06 No currency lens in the Sales Desk UI Medium

The API supports ?currency=USD on both /sales-desk/dashboard and /sales-desk/pipeline/overview, and both were verified switching correctly. Neither page exposes any control for it.

The Sales Desk dashboard renders in USD with no way to reach KES, while the main app dashboard does have a KES/USD selector — so the two halves of the product behave inconsistently. The rep filter exists on Pipeline (the rep cards) but not on the Sales Desk dashboard. Checklist item 5 asks for both "everywhere".

07 Sales Desk sub-nav ignores entitlements Low

Module Settings states that disabled modules disappear from navigation. The main app honours this — disabling Vendors removed it from Purchases and made /vendors redirect. The Sales Desk sidebar does not: with onboarding disabled, "Onboarding" stayed visible and clickable, landing the user on a 403 error page.

08 Parking does not refresh the scoreboard Low

After parking a deal, the stage strip and rep cards still showed pre-park figures (117 / 125 open); a manual reload corrected them to 116 / 124. Closing a deal does refresh correctly, so the park handler is just missing the re-fetch.

Module entitlements point the wrong way

09 Entitlements are self-service, and there is no Settings section Design

The intent is that a platform operator grants module access to each owner, and that owners get their own Settings area for their details and branding — a multi-tenant arrangement. What shipped does not do that.

IntendedAs built
A super-admin / platform role grants modules to an owner UserRole is only ADMIN, MANAGER, MEMBER — no platform role exists
Operator targets a specific owner GET/PATCH /owner/modules take no owner id; the service resolves a single owner profile
An owner cannot lift their own restriction Both endpoints are gated on require_role(UserRole.ADMIN) — the tenant's own admin, so an owner can re-enable anything
Many tenants owner_profiles holds 1 row; the export audit stamps "deployment_boundary": "single_organization"
Settings section holding both areas settings/modules is the only settings route, surfaced as a top-level nav item
Owners edit their details and branding in Settings Owner profile and logo have endpoints, but the only UI is OwnerProfileModal opened from inside the document editor

The one piece that already fits is storage: owner_module_settings is keyed by owner_profile_id, so the table survives a move to real multi-tenancy. The role model and the API surface do not.

Shape of the work — add a platform-operator role above ADMIN; re-scope the module endpoints to /platform/owners/{owner_id}/modules and restrict them to that role; give owners a real /settings section (business details, branding and logo, document defaults) with module entitlements read-only there. This is a multi-tenancy change, not a tweak — it deserves its own issue and an ADR, and it should not be squeezed into the go-live.

Fixed in this pass

Five UI defects surfaced during the walkthrough. All are fixed, type-checked, linted, and verified in the browser; the frontend build passes with them.

Expenses row overflowed

"Add Expense" was pushed past the right edge. Flex children default to min-width:auto, so the five tabs plus a 280px search box refused to shrink. Added min-w-0 and a non-shrinking button — overflow measured 88px, now 0.

Sidebar clipped its own footer

The rail was min-h-screen with an inner h-screen child inside 48px of padding, and overflow: visible — so 221px of nav and the whole user card were unreachable. Rebuilt as brand / scrolling nav / pinned footer. Overflow 221px → 0.

The two sidebars had diverged

Different background, active pill, text colour, radius and item metrics. Both now import one sidebar-styles module, restoring the pre-Sales-Desk palette, so they cannot drift apart again.

Invoice icon was oversized

The imported SVG hardcodes width="24" height="24" and size is not a valid SVG attribute, so SVGR ignored it while Lucide icons rendered at 18. A CSS size beats the attribute — every nav icon now measures 18×18.

Stray scrollbars in the chrome

Making the nav scrollable exposed a permanent scrollbar track down the rail, which reads as a rendering fault. Added a no-scrollbar utility — scrolling still works by wheel, trackpad, touch and keyboard.

Filter tabs wrapped off the row

gap-6 between tabs pushed the search box and primary action off the line. Tightened to gap-1 with non-wrapping tabs, so a full set now fits on one row. One shared component, so every page using it benefits.
